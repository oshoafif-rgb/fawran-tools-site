Why a link has %20 and %3D, and how to understand URL encoding

Noticed strange codes like %20 or %3D in long links? These are not errors or anything complicated — just a standard simple way for any data to arrive correctly over the internet without confusion with the main link symbols.

Why do we need link encoding in the first place?

The URL standard specifies a set of characters with a specific functional meaning (like & to separate parameters, ? to start the query, and spaces are not allowed at all). If your actual data (like a user search or file name) contains the same characters, it must be encoded first so it doesn’t get confused with the structure of the link itself.

How does encoding work?

Each special or unauthorized character is converted to a % sign followed by two hexadecimal symbols representing the numeric value of the character in the ASCII table. For example, the distance is converted to 20% (because 20 is the hexadecimal representation of the distance symbol), and a sign = Converts to %3D.

Common uses

  • Search data in links: Passing a search term containing spaces or special characters as a parameter in a link.
  • HTML form data: Automatically send form data via GET with encoded fields.
  • Sharing links containing Arabic text: Ensure that the link arrives correctly when copied for different platforms.
  • Manually building API requests: Make sure any data is encoded before adding it to a request link.

Frequently Asked Questions

Why is space specifically converted to %20?

20 is the hexadecimal representation of the space character in the ASCII table, and the % sign indicates that the following is an encoded code.

Do all Arabic characters need encoding in links?

Yes, any character outside the range of allowed basic characters requires encoding, so Arabic letters are converted to multiple % symbols.

Can I use + instead of %20 for space?

In the query part only, + is acceptable as an alternative, but %20 is the more precise and accepted standard in all parts of the link.

Does encoding a link change its actual destination?

No, encoding is just a safe alternative representation, and the browser automatically decodes it to reach the same original destination.

Summary

URL encoding is a simple mechanism to ensure your data is delivered correctly without confusion with the URL structure itself — once you understand the logic, you will be able to read any encoded URL or confidently build one yourself.
