Why your JSON file is rejected by the system even though it looks correct.

The file looks organized and perfectly readable, but the system rejects it with a vague error message like "Unexpected token." The problem is usually not with the format but a small structural detail that violates the official JSON standard.

The difference between "formatted" and "structurally correct"

Formatting only arranges the visual appearance of text (spaces, new lines), whereas validation checks that the structure itself fully complies with the official JSON standard rules. A text may be very nicely formatted visually, but at the same time structurally incorrect and will be rejected by any strict system.

The most common hidden mistakes that slip past the eye

An extra comma after the last item in a list or object is one of the most common mistakes and is hard to detect with the naked eye, especially in long files. Also, using a single quote (') instead of double quotes (") around text, or writing a numeric value in an unsupported format (like numbers with leading zeros) causes the entire file to be rejected.

Strict JSON rules that many forget

The official JSON standard requires: mandatory double quotes around every key and text (not single quotes), logical values must be true or false entirely in lowercase (not True or FALSE), and there is no support for comments at all (neither // nor /* */) even though they are accepted in many programming languages that take inspiration from JSON.

Frequently Asked Questions

What is the difference between formatting and validation?

Formatting organizes the visual appearance only, while validation checks that the structure complies with official standard rules.

Why does JSON sometimes work in one tool but not in another?

Some tools are more forgiving of minor mistakes, while strict production systems reject any deviation from the standard.

Do values with true or false need to be in lowercase?

Yes, the standard requires true, false, and null in all lowercase letters — any other format will be considered an error.

Is it possible to use comments inside a JSON file?

No, the official standard does not support comments at all, unlike similar formats like JSON5 or JSONC.
